# Лендинг промышленного оборудования Jack

## [Открыть сайт — rez1dennt.github.io/jack](https://rez1dennt.github.io/jack/)

Публичное превью автоматически обновляется после каждого изменения в ветке `main`.

Адаптивный HTML/CSS/JavaScript-лендинг с оригинальными изображениями и SVG-иконками, доступным бургер-меню, cookie-настройками, юридическими страницами и защищённым PHP-обработчиком заявок через PHPMailer 7.

## Что уже реализовано

- Desktop-композиция выверена по исходному скриншоту; отдельные раскладки предусмотрены для планшета и телефона.
- Форма проверяет имя, российский телефон и отдельное согласие; маска корректно вводится и удаляется.
- Сервер повторно валидирует данные, проверяет CSRF, Origin/Referer, honeypot, время заполнения, размер JSON и частоту запросов.
- SMTP-секреты находятся вне `public/`, ошибки PHPMailer не возвращаются посетителю.
- Cookie-баннер по умолчанию не включает аналитику или рекламу.
- `privacy.html`, `consent.html`, `robots.txt`, `sitemap.xml`, JSON-LD, Open Graph и manifest подготовлены с маркерами.
- Кнопка скачивания ведёт на рабочий предварительный PDF. Перед запуском замените его официальным листом поставщика.

## Локальный запуск и тесты

Требования: Node.js 22+, PHP 8.1+, Composer 2, PHP-расширения `openssl`, `mbstring`, `json` и `session`.

```powershell
npm ci
composer install
npx playwright install chromium
php -S 127.0.0.1:8080 -t public
```

В другом окне:

```powershell
npm run test:js
npm run test:e2e
Get-ChildItem tests/php/*.test.php | ForEach-Object { php -d zend.assertions=1 -d assert.exception=1 $_.FullName }
```

Автотесты не подключаются к реальному SMTP: письмо перехватывается тестовым транспортом.

## Развёртывание на Host-0

В панели хостинга выберите PHP 8.1 или новее, включите `openssl`, `mbstring`, `json`, `session`, а затем выпустите бесплатный SSL-сертификат. Сайт должен открываться только по HTTPS; перенаправление HTTP на HTTPS включите в панели хостинга.

Предпочтительная структура:

```text
/home/account/
  public_html/       <- содержимое public/
  server/            <- не доступен из браузера
  vendor/            <- зависимости Composer
  composer.json
  composer.lock
```

Если панель позволяет менять DocumentRoot, загрузите проект целиком и назначьте корнем домена каталог `public/`. Если доступен только `public_html`, скопируйте туда именно содержимое `public/`; `server/` и `vendor/` оставьте уровнем выше. Пути API рассчитаны на такую схему.

На сервере выполните:

```bash
composer install --no-dev --optimize-autoloader
cp server/config.example.php server/config.php
php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
```

Последняя команда создаёт секрет для `[[RANDOM_32_BYTE_SECRET]]`. Файл `server/config.php` запрещено добавлять в Git или помещать в `public_html`. Рекомендуемые права: `600` или `640` для `server/config.php`, `700` или `750` для `server/storage/`; процесс PHP должен иметь запись только в `server/storage/`.

Если Composer на тарифе недоступен, выполните установку локально и загрузите полученный `vendor/` рядом с `server/`.

## Настройка Google SMTP

1. Включите двухэтапную аутентификацию Google.
2. Создайте отдельный 16-значный пароль приложения: [официальная инструкция Google](https://support.google.com/mail/answer/185833?hl=ru).
3. Заполните приватный `server/config.php`: `smtp.gmail.com`, порт `587`, `tls`, полный адрес Gmail в `username` и `from_email`, пароль приложения в `password`, согласованный адрес получателя в `to_email`.
4. Не указывайте в `from_email` данные посетителя: заголовки должны формироваться только сервером.
5. После публикации отправьте одну контролируемую заявку и проверьте входящие и «Спам». Не включайте SMTP debug на рабочем сайте.

Параметры `smtp.gmail.com` и TLS/587 соответствуют [официальной инструкции Google Workspace](https://support.google.com/a/answer/176600?hl=ru). Пароль приложения может быть недоступен для управляемого аккаунта, Advanced Protection или конфигурации 2FA только с аппаратными ключами.

## Обязательные замены перед запуском

Замените маркеры во всех файлах, а не только на главной странице:

| Маркер | Что указать |
|---|---|
| `[[DOMAIN]]` | домен без `https://` и завершающего `/` |
| `[[LEGAL_NAME]]` | полное название организации или ИП |
| `[[INN]]` | ИНН оператора |
| `[[ADDRESS]]` | юридический адрес или согласованный город/адрес |
| `[[EMAIL]]` | email для обращений субъектов персональных данных |
| `[[PHONE]]` | телефон оператора |
| `[[RETENTION_PERIOD]]` | фактический и обоснованный срок хранения заявок |
| `[[SMTP_USERNAME]]` | полный адрес Google-аккаунта отправителя |
| `[[GOOGLE_APP_PASSWORD]]` | отдельный пароль приложения Google |
| `[[LEAD_RECIPIENT]]` | адрес, куда приходят заявки |
| `[[RANDOM_32_BYTE_SECRET]]` | результат команды генерации выше |

Проверка маркеров:

```powershell
rg -n "\[\[[A-Z0-9_]+\]\]" public server README.md
```

В опубликованных файлах `public/`, `privacy.html`, `consent.html`, `robots.txt` и `sitemap.xml` совпадений быть не должно. В `server/config.example.php` и этом README маркеры остаются как документация; реальные значения находятся только в `server/config.php`.

Также замените `public/assets/docs/jack-ms-100a.pdf` официальной спецификацией, подключите согласованный видеофайл и реальные ссылки на соцсети, подтвердите контакты, характеристики, кейс и право использования названия Jack.

## Юридический стоп-чек перед публикацией в РФ

Тексты в проекте являются техническими шаблонами, а не гарантией соответствия закону. Пока не указаны данные оператора и не описана фактическая инфраструктура обработки, публиковать форму как юридически готовую нельзя.

До запуска оператору необходимо:

- согласовать политику, согласие, срок хранения, перечень лиц с доступом и порядок удаления заявок;
- проверить обязанность уведомить Роскомнадзор до начала обработки и внести используемые меры и места хранения в документы;
- обеспечить требования локализации персональных данных граждан РФ;
- отдельно оценить Google SMTP. Передача имени и телефона в Gmail может быть трансграничной и при прямой отправке не обеспечивает российскую первичную базу сама по себе. Для строгого сценария используйте российский почтовый сервис или внедрите согласованную с юристом локальную первичную запись и процедуру трансграничной передачи;
- заключить необходимые договоры или поручения с обработчиками и ограничить доступ к почтовому ящику;
- не подключать аналитику, рекламные пиксели или сторонние виджеты до обновления политики и механизма согласия.

Официальные отправные точки: [раздел Роскомнадзора для операторов персональных данных](https://pd.rkn.gov.ru/operators-registry/notification/form/), [Федеральный закон № 152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/), [официальное опубликование изменений о локализации от 23.05.2025](https://publication.pravo.gov.ru/document/0001202505230035).

## Проверка после загрузки

1. Откройте главную, политику, согласие, sitemap и PDF по HTTPS.
2. Проверьте desktop, 768 px и 390 px; откройте и закройте бургер мышью, Tab и Escape.
3. Введите и полностью удалите телефон, затем проверьте пустую, ошибочную и успешную форму.
4. Отправьте одну заявку на контролируемый адрес и убедитесь, что письмо пришло без SMTP-диагностики в браузере.
5. Повторите отправку более пяти раз и проверьте ответ об ограничении частоты.
6. Проверьте, что `server/config.php`, `vendor/` и `server/storage/` недоступны по URL.
7. После замены домена проверьте canonical, Open Graph, JSON-LD, `robots.txt` и `sitemap.xml`.
