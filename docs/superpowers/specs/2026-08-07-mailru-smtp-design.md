# Интеграция формы с SMTP Mail.ru

## Цель

Подключить существующую форму обратной связи к ящику `tekstilopttorg@mail.ru`: этот адрес используется одновременно для SMTP-авторизации, отправки и получения заявок.

## Архитектура

- Браузер получает CSRF-токен через `GET /api/csrf.php` и отправляет JSON только в `POST /api/submit.php`.
- Сервер сохраняет существующие проверки: метод и тип содержимого, лимит размера, CSRF, Origin/Referer, honeypot, минимальное время заполнения, серверную валидацию и ограничение частоты запросов.
- `MailerTransport` отправляет письмо через PHPMailer 7 и SMTP Mail.ru.
- Основные параметры транспорта: `smtp.mail.ru`, порт `465`, SMTP-авторизация и SSL/TLS (`PHPMailer::ENCRYPTION_SMTPS`).
- Адрес `tekstilopttorg@mail.ru` используется в `username`, `from_email` и `to_email`. Данные посетителя никогда не подставляются в заголовок `From`.

## Хранение секретов

- SMTP-пароль хранится только в `server/config.php`.
- `server/config.php` остаётся исключённым из Git и не копируется в публичную директорию сайта.
- В `server/config.example.php`, тестах, документации, HTML и JavaScript секрет отсутствует.
- Сообщения об ошибках SMTP записываются только в серверный журнал без пароля и не возвращаются посетителю.

## Поток данных

1. Посетитель заполняет имя, телефон, необязательное описание задачи и подтверждает согласие.
2. Клиентская часть проверяет поля и отправляет JSON вместе с CSRF-токеном.
3. PHP повторно проверяет запрос и нормализует данные.
4. PHPMailer устанавливает защищённое соединение с `smtp.mail.ru:465` и отправляет письмо на `tekstilopttorg@mail.ru`.
5. При успехе форма очищается и показывает подтверждение. При ошибке посетитель видит нейтральное сообщение без технических подробностей.

## Ошибки и резервный вариант

- Основной транспорт — SSL/TLS на порту 465 согласно официальной конфигурации Mail.ru.
- Если рабочий хостинг блокирует исходящий порт 465, после подтверждения по журналу допускается переключение на порт 587 с STARTTLS.
- Если локальная среда блокирует внешние SMTP-соединения, функциональные тесты транспорта выполняются без реальной отправки, а контрольное письмо проверяется после загрузки на PHP-хостинг.

## Проверка

- PHP-тест подтверждает настройки Mail.ru, SMTPS, адреса отправителя и получателя, а также экранирование пользовательских данных.
- Все существующие PHP- и JavaScript-тесты должны пройти без регрессий.
- Выполняется синтаксическая проверка PHP-файлов.
- Выполняется поиск секрета и приватного конфигурационного файла среди отслеживаемых Git-файлов.
- При доступной сети отправляется одна контрольная заявка; иначе этот шаг переносится на рабочий хостинг.

## Ограничения развёртывания

SMTP-обработчик требует PHP 8.1+, Composer-зависимости и доступ сервера к `smtp.mail.ru`. Статическое размещение на GitHub Pages или Vercel само по себе не выполняет PHP-endpoint'ы формы.
